# Set 실습 — 명령어 드릴 72선

> 직접 redis-cli에 한 줄씩 입력하며 결과를 확인하라.
> **답을 보지 말고** 먼저 추측 → 입력 → 결과 비교 → 헷갈리면 메모.
> 다 풀면 Claude에게 "Set 실습 완료" → 함정(🪤) 위주 채점.

## 표기 규칙

- ★ ~ ★★★★★ : 난이도
- 🪤 : 함정 문제 (대부분 헷갈림)
- 🔀 : 집합 연산 (교집합/합집합/차집합)
- 🎲 : 랜덤 관련
- ⚠ : 실무에서 자주 실수하는 포인트
- `>` : redis-cli 입력 프롬프트

## 사전 준비

```bash
> FLUSHDB        # ⚠ 현재 DB만 비움. 다른 데이터 있으면 주의!
> DBSIZE         # 0 인지 확인
```

> 💡 Set은 "순서 없는, 중복 없는 모음". List와 가장 큰 차이 = **중복 불가 + 순서 없음 + 멤버십 검사가 빠름.**

## §1. SADD / SREM — 추가와 제거

### Q1. ★ 가장 기본
```
> SADD tags "rock"
> SADD tags "jazz"
> SADD tags "pop"
> SMEMBERS tags            ← 무엇이 들어있나? 순서는 보장될까?
```
=> 순서는 보장 안됨, rock jazz pop
---

### Q2. ★★ 🪤 중복 추가
```
> DEL tags
> SADD tags "rock"
> SADD tags "rock"         ← 같은 값 또 추가. 반환값은? (1? 0?)
> SCARD tags               ← 개수는? 1? 2?
```
> 함정: Set은 중복을 허용하지 않는다. SADD 반환값 = **새로 추가된 개수**.
=> 0, 1
---

### Q3. ★★ 여러 값 한 번에
```
> DEL tags
> SADD tags "a" "b" "c" "a"   ← "a"가 두 번. 반환값은? (4? 3?)
> SMEMBERS tags
```
=> 3

---

### Q4. ★★ 🪤 SADD 반환값의 의미 (중복 방지의 핵심)
```
> DEL favorite:user:1
> SADD favorite:user:1 "artist:10"    ← 반환값? (처음 찜)
> SADD favorite:user:1 "artist:10"    ← 반환값? (이미 찜함)
```
질문: 이 반환값(1/0)으로 "이미 찜한 아티스트인가?"를 어떻게 판단하나?
=> 1
=> 0
---

### Q5. ★ SREM 제거
```
> DEL tags
> SADD tags "a" "b" "c"
> SREM tags "b"            ← 반환값? 
> SMEMBERS tags
> SREM tags "zzz"          ← 없는 값 제거. 반환값?
```
=> 1
=> 0
---

### Q6. ★★ 🪤 마지막 멤버 제거하면?
```
> DEL s

> EXISTS s                 ← 키가 아직 있을까? (0? 1?)
```

## §2. SISMEMBER / SMISMEMBER / SCARD — 멤버십 검사 (Set의 존재 이유)

### Q7. ★ SISMEMBER — 있나 없나
```
> DEL tags
> SADD tags "rock" "jazz"
> SISMEMBER tags "rock"    ← 반환값? (1? 0?)
> SISMEMBER tags "pop"     ← 반환값?
```
> 💡 이 O(1) "있다/없다" 검사가 Set의 가장 큰 무기. List로 하면 O(N).
=> 1,
=> 0
---

### Q8. ★★ SMISMEMBER — 여러 개 한 번에 (Redis 6.2+)
```
> DEL tags
> SADD tags "rock" "jazz" "pop"
> SMISMEMBER tags "rock" "classic" "pop"   ← 결과 형태는? (각각 1/0)
```
=> 1 0 1
---

### Q9. ★ SCARD — 개수
```
> DEL s
> SADD s "a" "b" "c"
> SCARD s                  ← 3
> SCARD nope               ← 없는 키는?
```
=> 0
---

### Q10. ★★ 🪤 SISMEMBER vs LPOS(List) 성능 차이
```
> DEL myset mylist
> SADD myset "x"
> RPUSH mylist "x"
> SISMEMBER myset "x"      ← O(1)
> LPOS mylist "x"          ← O(N)
```
질문: "이 값이 집합에 있나?"를 자주 검사해야 한다면 List와 Set 중 무엇? 왜?
=> list 는 tail, head만 O(1) 이기 때문

## §3. SMEMBERS / SSCAN — 전체 조회

### Q11. ★ SMEMBERS

```
> SADD s "a" "b" "c"
> SMEMBERS s               ← 전체. 순서가 들어간 순서와 같나?
```
> ⚠ Set은 순서 보장 없음. 들어간 순서/정렬 순서 둘 다 아님.
=> 다르다
---

### Q12. ★★★ 🪤 ⚠ SMEMBERS의 위험
```

> SADD big a b c d e f g h i j   ← (작게 흉내만)
> SMEMBERS big
```
질문: 만약 `big`에 멤버가 **100만 개**라면 `SMEMBERS big`은 왜 위험한가? 대안은?
(힌트: 단일 스레드 블로킹 + List의 `LRANGE 0 -1`과 같은 함정)

---

### Q13. ★★ SSCAN — 커서 기반 순회
```
> DEL s
> SADD s a b c d e
> SSCAN s 0                ← 커서 0부터. 반환 형태는? (커서, 멤버들)
> SSCAN s 0 COUNT 2        ← COUNT 힌트
> SSCAN s 0 MATCH a*       ← 패턴 매칭
```
> 💡 운영에선 SMEMBERS 대신 SSCAN. KEYS→SCAN과 같은 원리.

## §4. SPOP / SRANDMEMBER — 랜덤 추출 (차이가 함정)

### Q14. ★★ 🎲 SPOP — 랜덤으로 꺼내며 제거
```
> DEL s
> SADD s "a" "b" "c" "d" "e"
> SPOP s                   ← 무엇이 나올지 예측 가능? 
> SCARD s                  ← 개수 줄었나?
```
=> 예측 불가능
=> 갯수 줄었음
---

### Q15. ★★ 🎲 SRANDMEMBER — 랜덤으로 보기만 (제거 X)
```
> DEL s
> SADD s "a" "b" "c" "d" "e"
> SRANDMEMBER s            ← 랜덤 1개
> SCARD s                  ← 개수 그대로? (SPOP과 차이!)
```
> 🪤 **SPOP = 꺼내고 지움 / SRANDMEMBER = 보기만 함.** 이 차이가 핵심.
=> 응 갯수는 그대로
---

### Q16. ★★★ 🎲🪤 count 옵션 — 양수 vs 음수
```
> DEL s
> SADD s "a" "b" "c"
> SRANDMEMBER s 2          ← 2개 (중복 없이)
> SRANDMEMBER s 5          ← 3개뿐인데 5개 요청. 몇 개? (중복?)
> SRANDMEMBER s -5         ← 음수 count. 결과는? (중복 허용?)
```
> 🪤 **양수 count = 중복 없이 최대 N개** / **음수 count = 중복 허용해서 정확히 |N|개.** 추첨/샘플링에서 갈린다.
=> 3개
=> 중복허용 5개 (a a)도 나올수있음
---

### Q17. ★★★ 🎲 SPOP count
```
> DEL s
> SADD s "a" "b" "c" "d" "e"
> SPOP s 2                 ← 한 번에 2개 꺼내고 제거
> SMEMBERS s
> SPOP s 100               ← 남은 것보다 많이. 몇 개?
> EXISTS s                 ← 다 꺼내면 키는?
```
=> 모두
=> 0
---

### Q18. ★★ 🎲 추첨 미션 — 당첨자 뽑기
```
> DEL raffle
> SADD raffle "user1" "user2" "user3" "user4" "user5"
> SPOP raffle 2            ← 당첨자 2명 (중복 없이, 뽑힌 사람은 풀에서 제거)
```
질문: "중복 없는 당첨자 N명"엔 SPOP count가 왜 적합한가? SRANDMEMBER 양수와는 뭐가 다른가?

## §5. 집합 연산 🔀 SINTER / SUNION / SDIFF (Set의 꽃)

### Q19. ★★ 🔀 SINTER — 교집합
```
> DEL a b
> SADD a "rock" "jazz" "pop"
> SADD b "jazz" "pop" "classic"
> SINTER a b               ← 둘 다 있는 것? 
```
> 💡 "두 사용자가 함께 찜한 아티스트" = SINTER. 공통 관심사의 핵심.
=> jazz
---

### Q20. ★★ 🔀 SUNION — 합집합
```
> SUNION a b               ← 둘을 합친 것 (중복 자동 제거)
```

---

### Q21. ★★ 🔀 SDIFF — 차집합 (순서 주의)
```
> SDIFF a b                ← a에는 있지만 b에는 없는 것
> SDIFF b a                ← b에는 있지만 a에는 없는 것 (결과 다름!)
```
> 🪤 SDIFF는 **첫 번째 키 기준**. 인자 순서가 결과를 바꾼다.

---

### Q22. ★★★ 🔀 여러 집합 연산
```
> DEL a b c
> SADD a "1" "2" "3" "4"
> SADD b "2" "3" "4" "5"
> SADD c "3" "4" "5" "6"
> SINTER a b c             ← 셋 다 있는 것?
> SUNION a b c             ← 다 합치면?
> SDIFF a b c              ← a에서 b,c에 있는 걸 뺀 것?
```
=> 3 4 
=> 1 2 3 4 5 6
=> 1
---

### Q23. ★★★ 🔀 SINTERSTORE — 결과를 저장
```
> DEL a b dest
> SADD a "x" "y" "z"
> SADD b "y" "z" "w"
> SINTERSTORE dest a b     ← 교집합을 dest에 저장. 반환값은? (개수)
> SMEMBERS dest
```
> 💡 STORE 버전은 결과를 새 키로. 재사용/캐싱에 유용. SUNIONSTORE, SDIFFSTORE도 동일.
=> 2
---

### Q24. ★★★ 🔀 SINTERCARD — 교집합 "개수만" (Redis 7.0+)
```
> DEL a b
> SADD a "1" "2" "3" "4"
> SADD b "2" "3" "4" "5"
> SINTERCARD 2 a b         ← 교집합 크기만 반환 (멤버 안 가져옴)
> SINTERCARD 2 a b LIMIT 2 ← 최대 2까지만 세고 멈춤
```
> 💡 "공통 친구 몇 명?"처럼 개수만 필요할 때, 멤버 전체를 안 가져와서 효율적.

---

### Q25. ★★★ 🪤 🔀 없는 키와의 연산
```
> DEL a nope
> SADD a "1" "2"
> SINTER a nope            ← 없는 키와 교집합. 결과는?
> SUNION a nope            ← 없는 키와 합집합. 결과는?
```
> 힌트: 없는 키 = 빈 집합으로 취급.
=> empty
=> 1 2

### Q26. ★★★★ 🔀 ⚠ 큰 집합 연산의 비용


## §7. 빈 집합과 키 생명주기 ⚠🪤

### Q29. ★★★ 🪤 빈 집합은 키가 사라진다
```
> DEL s
> SADD s "x"
> EXISTS s                 ← 1
> SPOP s                   ← "x"
> EXISTS s                 ← ??? 0? 1?
> SCARD s                  ← ???
> TYPE s                   ← ???
```
> **Redis List/Set/Hash/ZSet 공통 규칙**: 컬렉션이 비면 **키 자체가 자동 삭제**.
> → 빈 집합이라는 상태는 존재하지 않는다.

## §8. 인코딩 / 운영 / 함정

### Q33. ★★★ 내부 인코딩 — intset
```
> DEL ints
> SADD ints 1 2 3 100 50
> OBJECT ENCODING ints     ← 정수만 넣으면? (intset?)
> SADD ints "hello"        ← 문자열 추가하면?
> OBJECT ENCODING ints     ← 인코딩 바뀌나?
```
> 💡 **정수만 = intset**(정렬된 정수 배열, 메모리 효율↑). 문자열 섞이면 listpack/hashtable로 전환.

---

### Q34. ★★★ 내부 인코딩 — listpack → hashtable
```
> DEL small
> SADD small "a" "b" "c"
> OBJECT ENCODING small    ← 작은 문자열 집합? (listpack)

> DEL big
> (128개 넘게 또는 긴 값 추가)
> OBJECT ENCODING big      ← hashtable로 바뀌는 경계 찾기
```
> 작은 집합 = `listpack`(또는 정수면 intset), 커지면 = `hashtable`. 경계: `set-max-listpack-entries`(기본 128), `set-max-intset-entries`.

---

### Q35. ★★ 🪤 WRONGTYPE
```
> DEL k
> SET k "i am a string"
> SADD k "x"               ← String 키에 SADD. 어떤 에러?
```
> Redis는 키 단위 타입 고정. String 키에 Set 명령 = WRONGTYPE.

---

### Q36. ★★ UNLINK로 큰 집합 삭제
```
> DEL big
> SADD big a b c d e
> UNLINK big               ← DEL 대신 비동기 삭제
> EXISTS big
```
> ⚠ 멤버 수십만~수백만 집합을 `DEL`하면 단일 스레드가 막힌다. `UNLINK`로 비동기 회수.
