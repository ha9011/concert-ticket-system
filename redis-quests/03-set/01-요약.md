# Set 실습 — 개념 정리 & 실무 활용 요약

> 72문항 실습 후 가볍게 읽으며 머릿속 정리용. 문법보다 **"왜 이 명령어가 있고, 실무에서 어떻게 쓰이는가"**에 무게.
> Set은 한 문장으로: **"순서 없는, 중복 없는 멤버 모음. 멤버십 검사와 집합 연산이 빠르다."**

---

## §0. Set이란 무엇인가 — 한 장 정리

```
   Set s = { "rock", "jazz", "pop" }     ← 순서 없음, 중복 없음

   SADD s "rock"   → 이미 있으면 무시 (반환 0)
   SISMEMBER s "rock" → 1 (있다)  ← O(1) 멤버십 검사
   SINTER a b      → 두 집합의 교집합
```

- **순서 없음**: 넣은 순서/정렬 순서 둘 다 보장 안 됨. (순서 필요하면 List, 정렬 필요하면 ZSet)
- **중복 없음**: 같은 값을 여러 번 넣어도 1개. `SADD` 반환값으로 "신규냐 중복이냐" 판단.
- **멤버십 검사 O(1)**: "이 값 있어?"(`SISMEMBER`)가 매우 빠름 — Set의 존재 이유.
- **집합 연산**: 교집합/합집합/차집합(`SINTER`/`SUNION`/`SDIFF`)을 명령 하나로.
- **빈 컬렉션 = 키 삭제**: 멤버가 0개가 되면 키 자체가 사라진다. "빈 Set" 상태는 없다.

> 💡 List가 "순서 있는 줄"이라면, Set은 "중복 없는 주머니". **"있다/없다" 검사 + 집합 연산이 필요하면 Set이 1순위.**

## §1. 추가·제거 — SADD / SREM

| 명령어 | 동작 | 반환값 |
|---|---|---|
| `SADD k m [m...]` | 멤버 추가 | **새로 추가된 개수** (중복은 제외) |
| `SREM k m [m...]` | 멤버 제거 | 실제 제거된 개수 |
| `SMOVE src dst m` | src→dst로 멤버 원자적 이동 | 1(이동), 0(src에 없음) |

### 핵심 포인트

- **🪤 SADD 반환값 = "새로 들어간 수"** — 이미 있던 멤버는 안 셈. `SADD favorite "artist:10"`이 **1이면 신규 찜, 0이면 이미 찜함**. 이 한 줄로 "중복 방지 + 이미 했는지 판단"이 동시에 된다.
- **여러 멤버 한 번에** — `SADD k a b c`. 인자 중 중복은 알아서 1개로.
- **SREM도 여러 개** — 없는 멤버 제거는 무시(반환에 안 셈).
- **마지막 멤버 제거 → 키 삭제** (§0 규칙).

## §2. 멤버십 검사 — SISMEMBER / SMISMEMBER / SCARD (Set의 존재 이유)

| 명령어 | 동작 | 복잡도 |
|---|---|---|
| `SISMEMBER k m` | 있나? (1/0) | **O(1)** |
| `SMISMEMBER k m [m...]` | 여러 개 한 번에 (6.2+) | O(N) (N=물어본 수) |
| `SCARD k` | 멤버 개수 | O(1) |

### 핵심 포인트

- **이 O(1) 멤버십 검사가 Set의 가장 큰 무기.** "이 사용자가 이미 좋아요 눌렀나?", "이 IP가 차단 목록에 있나?", "이미 본 상품인가?" — List로 하면 `LPOS`가 O(N)이지만 Set은 O(1).
- **SMISMEMBER**(6.2+)로 여러 멤버를 한 번에 검사 → 왕복 횟수 절약.
- **SCARD는 O(1)** — 멤버를 안 세고 메타에서 즉시 반환. "좋아요 수", "찜한 개수"에 적합.

---

## §3. 전체 조회 — SMEMBERS / SSCAN

| 명령어 | 동작 | 비고 |
|---|---|---|
| `SMEMBERS k` | 전체 멤버 | **O(N) — 큰 Set에 위험** |
| `SSCAN k cursor [MATCH p] [COUNT n]` | 커서 순회 | 운영 안전 |

### 핵심 포인트

- **🚨 `SMEMBERS`는 큰 집합에서 위험** — 멤버 100만 개면 전부 직렬화해 한 번에 쏟아냄. 단일 스레드 블로킹 + 대역폭 폭발. List의 `LRANGE 0 -1`과 똑같은 함정.
- **운영에선 `SSCAN`** — 커서로 조금씩 순회. `KEYS`→`SCAN`과 같은 원리. MATCH로 패턴, COUNT로 배치 힌트.
- **순서 보장 없음** — SMEMBERS/SSCAN 결과 순서에 의존하지 말 것.

## §4. 랜덤 추출 — SPOP / SRANDMEMBER (차이가 함정)

| 명령어 | 동작 | 제거? |
|---|---|---|
| `SPOP k [count]` | 랜덤 멤버 꺼냄 | **제거함** |
| `SRANDMEMBER k [count]` | 랜덤 멤버 봄 | **제거 안 함** |

### 핵심 포인트 — count 부호 (헷갈림 1순위)

| 명령 | 동작 |
|---|---|
| `SPOP k N` | 랜덤 N개 꺼내고 **제거** (중복 없음) |
| `SRANDMEMBER k N` (양수) | 랜덤 **최대 N개**, **중복 없이** (N>크기면 전체만) |
| `SRANDMEMBER k -N` (음수) | **정확히 N개**, **중복 허용** (같은 멤버 또 나올 수 있음) |

### 실무 활용

- **중복 없는 당첨자 뽑기** → `SPOP raffle 3` (뽑힌 사람은 풀에서 빠짐).
- **추첨 후보 미리보기**(풀 유지) → `SRANDMEMBER raffle 3` (양수, 중복 없이).
- **중복 허용 샘플링**(주사위처럼) → `SRANDMEMBER k -10` (음수).

> 🪤 **SPOP = 꺼내고 지움 / SRANDMEMBER = 보기만.** 당첨자는 SPOP, 미리보기는 SRANDMEMBER.

## §5. 집합 연산 🔀 SINTER / SUNION / SDIFF (Set의 꽃)

| 명령어 | 동작 | 비고 |
|---|---|---|
| `SINTER k [k...]` | 교집합 (모두에 있는 것) | 공통 |
| `SUNION k [k...]` | 합집합 (어디든 있는 것) | 중복 제거 |
| `SDIFF k [k...]` | 차집합 (**첫 키**엔 있고 나머지엔 없는 것) | 순서 중요 |
| `S*STORE dest ...` | 결과를 dest 키에 저장 | 반환=개수 |
| `SINTERCARD numkeys k... [LIMIT n]` | 교집합 **개수만** (7.0+) | 멤버 안 가져옴 |

### 핵심 포인트

- **교집합(SINTER) = "공통"** — 두 사용자가 함께 찜한 아티스트, 공통 친구, 공통 태그.
- **차집합(SDIFF) = "너에겐 있고 나에겐 없는 것"** — 추천(친구는 봤는데 나는 안 본 것). **🪤 첫 키 기준**이라 `SDIFF a b` ≠ `SDIFF b a`.
- **STORE 버전** — 결과를 새 키로 저장해 재사용/캐싱. 큰 연산 결과를 한 번 만들고 여러 번 읽을 때.
- **SINTERCARD**(7.0+) — "공통 몇 개?"만 필요할 때 멤버 전체를 안 만들어서 효율적. `LIMIT`으로 조기 종료.
- **없는 키 = 빈 집합**으로 취급. (SINTER에 빈 키 끼면 결과는 공집합)

### 🚨 비용 주의

- 큰 집합끼리 SINTER/SUNION은 **O(전체 멤버 수)**. 수백만 × 수백만이면 단일 스레드를 오래 잡는다.
- 개수만 필요하면 `SINTERCARD`, 결과 재사용이면 `S*STORE`, 정말 크면 **애플리케이션/배치로 분산**.

## §6. 인코딩 / 운영

### 핵심 포인트

- **인코딩 3단계**:
  - **intset** — 멤버가 **전부 정수**일 때. 정렬된 정수 배열, 메모리 최강 효율.
  - **listpack** — 작은 문자열 집합 (Redis 7.2+).
  - **hashtable** — 커지거나 문자열 섞이면. O(1) 보장.
  - 경계: `set-max-intset-entries`, `set-max-listpack-entries`(기본 128), `set-max-listpack-value`.
- **big key 주의** — 멤버 수십만~수백만 집합은 big key. `DEL`은 동기 블로킹 → **`UNLINK`로 비동기 삭제**. `SMEMBERS` 금지(SSCAN 사용).
- **WRONGTYPE** — String/List 키에 Set 명령 = 에러. 키 단위 타입 고정.

## 🎯 Set 핵심 패턴 8개 (실무 빈출)

1. **`SADD` 반환값(1/0)** — 중복 방지 + "이미 했나?" 판단 (좋아요·찜·투표 1회 제한)
2. **`SISMEMBER`** — O(1) 멤버십 검사 (차단 목록·권한·이미 본 항목)
3. **`SCARD`** — 개수 (좋아요 수·찜 수·태그 수)
4. **`SINTER`** — 공통 (함께 찜한 아티스트·공통 친구·공통 태그)
5. **`SDIFF`** — 추천 (친구는 했지만 나는 안 한 것 = 협업 필터링 기초)
6. **`SPOP count`** — 중복 없는 추첨/당첨자
7. **태그 양방향 인덱스** — `tags:item:{id}` ↔ `items:tag:{name}`
8. **`SADD`로 유니크 카운트** — 정확한 유니크 방문자 (대규모면 HyperLogLog로)

---

## ⚠️ 운영에서 깨지기 쉬운 약속 6가지

1. **`SMEMBERS`를 큰 집합에 쓰지 않는다** — `SSCAN`으로.
2. **빈 집합은 키가 사라진다** — `EXISTS`로 존재 체크 시 혼동 금지(`SCARD` 0과 키 없음 구분).
3. **big key 집합은 `UNLINK`로 지운다** — `DEL`은 블로킹.
4. **큰 집합 연산(SINTER/SUNION)은 비싸다** — 개수만이면 SINTERCARD, 결과 재사용은 STORE.
5. **SDIFF는 첫 키 기준** — 인자 순서가 결과를 바꾼다.
6. **SPOP(제거) vs SRANDMEMBER(유지)** 를 혼동하지 않는다.

## 📌 면접에서 잘 나오는 비교 질문

| 질문 | 답 |
|---|---|
| List vs Set | List=순서O·중복O, Set=순서X·중복X·멤버십 O(1). |
| SISMEMBER가 왜 빠른가 | 해시 기반 O(1). List의 LPOS는 O(N). |
| SPOP vs SRANDMEMBER | SPOP은 꺼내며 제거, SRANDMEMBER는 보기만. |
| SRANDMEMBER 양수 vs 음수 count | 양수=중복없이 최대N, 음수=중복허용 정확히 N. |
| intset이 뭔가 | 정수만 든 Set의 메모리 효율 인코딩(정렬 정수 배열). |
| 유니크 카운트: Set vs HyperLogLog | Set=정확·메모리 큼, HLL=근사(0.81% 오차)·12KB 고정. |
| 유니크 카운트: Set vs Bitmap | Bitmap은 멤버가 정수 ID일 때 비트로 초압축. |
| 공통 친구 어떻게 | `SINTER`(멤버) 또는 `SINTERCARD`(개수만). |

---

## Set vs Bitmap vs HyperLogLog (유니크 카운트 3총사)

"중복 없는 개수를 세는" 같은 목적이라도 셋이 다르다:

| | 정확도 | 메모리 | 멤버 조회 | 언제 |
|---|---|---|---|---|
| **Set** | 정확 | 큼 (멤버당) | 가능(SMEMBERS) | 멤버 목록도 필요할 때 |
| **Bitmap** | 정확 | 초압축 (멤버=정수 ID일 때) | 비트 위치로 | 사용자 ID가 정수일 때 출석/접속 |
| **HyperLogLog** | 근사(±0.81%) | 12KB 고정 | 불가 | 수억 유니크의 "대략 수"만 |

> 핵심: **목록·정확도 필요 = Set / 정수 ID 출석 = Bitmap / 대규모 근사 카운트 = HyperLogLog.**
