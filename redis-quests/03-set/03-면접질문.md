## A. 기본 구조

### Q1. Set을 한 문장으로 정의하라.
<details><summary>답</summary>

**순서 없고 중복 없는 멤버들의 모음.** 멤버십 검사(있다/없다)가 O(1)이고, 집합 연산(교집합·합집합·차집합)을 명령 하나로 지원.
</details>

### Q2. List와 Set의 핵심 차이 3가지는?
<details><summary>답</summary>

1. **중복**: List 허용 / Set 불가.
2. **순서**: List 있음 / Set 없음.
3. **멤버십 검사**: List `LPOS` O(N) / Set `SISMEMBER` O(1).
→ "순서 필요"=List, "있다/없다·집합 연산"=Set, "정렬 필요"=ZSet.
</details>

### Q3. 🪤 `SADD`의 반환값은 무엇인가? 왜 중요한가?
<details><summary>답</summary>

**새로 추가된 멤버 수**(이미 있던 건 제외). `SADD favorite x`가 1이면 신규, 0이면 이미 있음. → **중복 방지 + "이미 했나" 판단**을 이 반환값 하나로. 좋아요·찜·투표 1회 제한의 핵심.
</details>

### Q4. Set의 멤버가 모두 제거되면 키는 어떻게 되나?
<details><summary>답</summary>

**키 자체가 자동 삭제**된다. (List/Set/Hash/ZSet 공통) "빈 Set"이라는 상태는 없다. → `EXISTS` 0, `SCARD` 0.
</details>

### Q5. `SCARD`의 복잡도는?
<details><summary>답</summary>

**O(1).** 멤버를 세지 않고 메타데이터에서 즉시 반환. 좋아요 수·찜 수에 적합.
</details>

## B. 명령어 비교

### Q6. 🪤 `SPOP`과 `SRANDMEMBER`의 차이는?
<details><summary>답</summary>

- `SPOP`: 랜덤 멤버를 꺼내고 **제거**한다.
- `SRANDMEMBER`: 랜덤 멤버를 **보기만**(제거 안 함).
→ 당첨자 확정=SPOP, 후보 미리보기=SRANDMEMBER.
</details>

### Q7. 🪤 `SRANDMEMBER key 5`와 `SRANDMEMBER key -5`의 차이는?
<details><summary>답</summary>

- **양수(5)**: 중복 없이 **최대 5개**(집합이 작으면 그만큼만).
- **음수(-5)**: 중복 허용해 **정확히 5개**(같은 멤버 또 나올 수 있음).
→ 중복 없는 샘플=양수, 중복 허용 샘플(주사위)=음수.
</details>

### Q8. "이 값이 집합에 있나?"를 자주 검사한다. List vs Set?
<details><summary>답</summary>

**Set.** `SISMEMBER` O(1) vs List `LPOS` O(N). 차단 목록·권한·이미 본 항목 등은 Set이 표준.
</details>

### Q9. 여러 멤버의 존재를 한 번에 검사하는 명령은?
<details><summary>답</summary>

**`SMISMEMBER key m1 m2 ...`** (Redis 6.2+). 각각 1/0 배열 반환. 왕복 횟수 절약.
</details>

### Q10. 멤버를 한 집합에서 다른 집합으로 원자적으로 옮기는 명령은?
<details><summary>답</summary>

**`SMOVE src dst member`.** 반환 1(이동 성공)/0(src에 없음). 원자적이라 중간 끊김 없음.
</details>

## C. 집합 연산

### Q11. SINTER / SUNION / SDIFF는 각각?
<details><summary>답</summary>

- `SINTER`: 교집합 (모든 집합에 있는 것).
- `SUNION`: 합집합 (어디든 있는 것, 중복 제거).
- `SDIFF`: 차집합 (**첫 키**엔 있고 나머지엔 없는 것).
</details>

### Q12. 🪤 `SDIFF a b`와 `SDIFF b a`는 같은가?
<details><summary>답</summary>

**다르다.** SDIFF는 **첫 번째 키 기준**. `SDIFF a b` = a에만 있는 것, `SDIFF b a` = b에만 있는 것. 인자 순서가 결과를 바꾼다.
</details>

### Q13. 교집합 결과를 새 키에 저장하려면?
<details><summary>답</summary>

**`SINTERSTORE dest k1 k2`.** 반환값은 결과 집합의 크기(개수). 재사용/캐싱용. `SUNIONSTORE`, `SDIFFSTORE`도 동일.
</details>

### Q14. 교집합의 "개수만" 필요할 때 효율적인 명령은? (7.0+)
<details><summary>답</summary>

**`SINTERCARD numkeys k1 k2 [LIMIT n]`.** 멤버 전체를 만들지 않고 크기만 반환. `LIMIT`으로 조기 종료 가능. "공통 친구 몇 명?"에 적합.
</details>

### Q15. 🪤 없는 키와 SINTER/SUNION을 하면?
<details><summary>답</summary>

없는 키 = **빈 집합**으로 취급. SINTER에 빈 키가 끼면 결과는 **공집합**, SUNION은 나머지 집합 그대로.
</details>

### Q16. "(록 OR 재즈) AND 내한" 같은 복합 태그 필터는?
<details><summary>답</summary>

단계 조합: `SUNIONSTORE tmp rock jazz` → `SINTER tmp overseas`. 자주 쓰면 STORE+TTL 캐싱. 너무 복잡·대규모면 검색 엔진(ES)으로.
</details>

### Q17. 큰 집합끼리 SINTER의 위험은?
<details><summary>답</summary>

멤버 수에 비례하는 비용(최악 O(전체 멤버)). **단일 스레드라 그동안 다른 명령이 다 밀린다.** → 개수만이면 SINTERCARD, 결과 재사용은 STORE, 후보 좁히기, 배치/비실시간으로.
</details>

## D. 인코딩

### Q18. Set의 내부 인코딩 종류는?
<details><summary>답</summary>

1. **intset** — 멤버가 전부 정수일 때(정렬된 정수 배열, 최강 메모리 효율).
2. **listpack** — 작은 문자열 집합(7.2+).
3. **hashtable** — 커지거나 문자열 섞이면(O(1) 보장).
</details>

### Q19. 🪤 intset에 문자열을 추가하면?
<details><summary>답</summary>

intset은 정수 전용이라, 문자열이 들어오면 **listpack 또는 hashtable로 전환**된다. 한 번 전환되면 다시 intset으로 안 돌아옴.
</details>

### Q20. intset/listpack → hashtable 전환 경계는?
<details><summary>답</summary>

`set-max-intset-entries`, `set-max-listpack-entries`(기본 128), `set-max-listpack-value`(멤버 길이). 초과하면 hashtable로. 작게 유지하면 메모리 효율↑.
</details>

### Q21. intset이 메모리에 유리한 이유는?
<details><summary>답</summary>

해시 테이블의 포인터·버킷 오버헤드 없이 **정렬된 정수 배열**로 연속 저장. 정수 ID 집합(작은 규모)에 최적.
</details>

## E. 유니크 카운트 비교 (Set vs Bitmap vs HyperLogLog)

### Q22. 정확한 유니크 카운트 + 멤버 목록도 필요하면?
<details><summary>답</summary>

**Set.** `SADD` + `SCARD`(개수) + `SMEMBERS/SISMEMBER`(목록·검사). 정확하지만 멤버당 메모리를 쓴다.
</details>

### Q23. 🪤 Set과 HyperLogLog의 차이는?
<details><summary>답</summary>

- **Set**: 정확, 멤버 조회 가능, 메모리 큼(멤버 수 비례).
- **HyperLogLog**: 근사(약 0.81% 표준 오차), 멤버 조회 **불가**, **최대 약 12KB**.
→ "대략 몇 명"만 필요한 수억 규모 유니크 카운트엔 HLL.
</details>

### Q24. 사용자 ID가 촘촘한 정수이고 출석/접속을 초압축으로 세려면?
<details><summary>답</summary>

**Bitmap.** `SETBIT active:{date} {userId} 1` + `BITCOUNT`. 1명=1비트(1000만명≈1.2MB). 단, ID가 너무 듬성듬성 크면 높은 offset 때문에 메모리가 커지므로 상한이 예측 가능해야 한다. 연속 출석은 `BITOP AND`.
</details>

### Q25. HyperLogLog로 "주간 유니크"를 구하려면?
<details><summary>답</summary>

**`PFMERGE`** 로 7일 HLL을 병합 후 `PFCOUNT`. Set의 SUNION을 무거운 비용 없이 근사. 단 교집합(공통)은 HLL로 정확히 안 됨.
</details>

## F. 운영 함정

### Q26. 🪤 큰 Set 전체 조회 시 SMEMBERS를 쓰면 안 되는 이유는?
<details><summary>답</summary>

O(N)으로 전 멤버를 한 번에 직렬화·전송 → **단일 스레드 블로킹**(다른 명령 대기). List의 `LRANGE 0 -1`과 같은 함정. → **`SSCAN`** 으로 커서 순회.
</details>

### Q27. big key Set을 삭제할 때 주의점은?
<details><summary>답</summary>

`DEL`은 동기 회수라 큰 Set이면 블로킹. **`UNLINK`로 비동기 삭제.** 모니터링은 `--bigkeys`, `MEMORY USAGE`.
</details>

### Q28. 🪤 `EXISTS`로 "사용자가 찜 목록을 가졌나" 판단하면 생기는 문제는?
<details><summary>답</summary>

찜을 다 취소하면 **빈 Set → 키 소멸 → EXISTS 0**. "데이터 손실"로 오해 가능. 빈 컬렉션과 키 없음을 구분해야. 진짜 이력은 DB로.
</details>

### Q29. Set 멤버에 개별 TTL을 걸 수 있나?
<details><summary>답</summary>

**불가.** TTL은 **키 단위**만. 멤버별 만료(예: 기간제 차단)가 필요하면 ZSet(score=만료시각)+주기 정리, 또는 멤버마다 별도 키로 설계.
</details>

### Q30. String 키에 SADD 하면?
<details><summary>답</summary>

**WRONGTYPE 에러.** 키 단위로 타입 고정. 네이밍 컨벤션으로 타입 분리, `TYPE key`로 디버깅.
</details>

## G. 실전

### Q31. "두 사용자의 공통 관심사"와 "추천"을 Set으로 어떻게?
<details><summary>답</summary>

- 공통: `SINTER favorite:user:A favorite:user:B` (또는 개수만 `SINTERCARD`).
- 추천: `SDIFF favorite:user:B favorite:user:A` = "비슷한 친구는 찜했지만 나는 안 찜한 것" = 협업 필터링 기초.
</details>

### Q32. 중복 없는 당첨자 N명 추첨을 안전하게 하려면?
<details><summary>답</summary>

**`SPOP raffle N`** 한 번. "뽑기+제거"가 원자적이라 중복 당첨 불가. SRANDMEMBER+SREM 분리는 레이스로 중복 위험. 가중 추첨은 ZSet. 결과는 DB에도 기록(휘발 대비).
</details>

### Q33. 🪤 "아티스트 새 공연 알림"에서 Set과 List의 역할 분담은?
<details><summary>답</summary>

- **Set** = "누가 대상인가"(`fans:artist:{id}`, 중복 없는 팬 집합) — 멤버십·대상 선정.
- **List** = "각자에게 시간순 전달"(`feed:user:{id}`, Fan-out on write) — 개인 피드.
→ **대상 선정은 Set, 전달은 List.** 팬이 매우 많으면 SSCAN으로 나눠 처리 또는 셀럽은 Fan-out on read.
</details>

## 마무리 — 한 줄 정리들

- **SADD 반환값(1/0)** = 중복 방지 + 이미 했나 판단.
- **SISMEMBER O(1)** = Set의 존재 이유 (List는 O(N)).
- **SPOP(제거) vs SRANDMEMBER(유지)**, **양수(중복X) vs 음수(중복O)**.
- **SINTER=공통, SDIFF=추천(첫 키 기준), SINTERCARD=개수만, STORE=캐싱.**
- **intset(정수)→listpack→hashtable**, 빈 Set=키 소멸.
- **유니크 카운트: 목록·정확=Set / 정수ID=Bitmap / 대규모 근사=HyperLogLog.**
- **SMEMBERS/큰 집합 연산은 단일 스레드 블로킹** — SSCAN·SINTERCARD·배치로.
- **진실은 DB, Set은 효율·실시간 뷰.**

> Set을 완주하면 → 로드맵상 다음은 **Sorted Set(ZSet)**. "순서 없는 Set"에 **점수(score) 정렬**이 붙으면 랭킹·대기열·우선순위·가중추첨이 열린다.
