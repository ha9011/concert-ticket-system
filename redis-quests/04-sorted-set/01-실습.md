# Sorted Set 실습 — 명령어 드릴 72선

> 직접 redis-cli에 한 줄씩 입력하며 결과를 확인하라.
> **답을 보지 말고** 먼저 추측 → 입력 → 결과 비교 → 헷갈리면 메모.
> 다 풀면 Claude에게 "ZSet 실습 완료" → 함정(🪤) 위주 채점.

## 표기 규칙

- ★ ~ ★★★★★ : 난이도
- 🪤 : 함정 문제 (대부분 헷갈림)
- 🏆 : 랭킹/리더보드 패턴
- 🎟 : 대기열/Rate Limit 패턴
- 🔀 : 집합 연산
- ⚠ : 실무에서 자주 실수하는 포인트
- `>` : redis-cli 입력 프롬프트

## 사전 준비

```bash
> FLUSHDB        # ⚠ 현재 DB만 비움. 다른 데이터 있으면 주의!
> DBSIZE         # 0 인지 확인
```

> 💡 ZSet = "Set + 각 멤버에 score(점수)". score 순으로 자동 정렬된다. 랭킹/범위/순위가 O(log N).

## §1. ZADD / ZSCORE / ZINCRBY — 추가와 점수

### Q1. ★ 가장 기본
```
> ZADD board 100 "alice"
> ZADD board 200 "bob"
> ZADD board 150 "carol"
> ZRANGE board 0 -1 WITHSCORES    ← 어떤 순서로 나오나? (score 오름차순?)
```

---

### Q2. ★★ 🪤 같은 멤버 다시 ZADD
```
> DEL board
> ZADD board 100 "alice"
> ZADD board 250 "alice"          ← 같은 멤버 다른 score. 반환값? 추가? 갱신?
> ZSCORE board "alice"            ← 100? 250?
> ZCARD board                     ← 1? 2?
```
> 함정: 멤버는 유일. 같은 멤버 ZADD는 **score를 갱신**(덮어씀). 반환값=새로 추가된 멤버 수.

---

### Q3. ★★ 여러 개 한 번에
```
> DEL board
> ZADD board 100 "a" 200 "b" 300 "c"   ← score member score member ...
> ZRANGE board 0 -1 WITHSCORES
```

---

### Q4. ★★ ZSCORE / ZMSCORE
```
> ZSCORE board "b"                ← "b"의 점수?
> ZSCORE board "nope"             ← 없는 멤버?
> ZMSCORE board "a" "nope" "c"    ← 여러 개 한 번에 (6.2+)
```

---

### Q5. ★★ 🏆 ZINCRBY — 점수 증가
```
> DEL game
> ZADD game 100 "player1"
> ZINCRBY game 50 "player1"       ← 점수 +50. 반환값? (150?)
> ZINCRBY game 30 "newbie"        ← 없는 멤버에 ZINCRBY. 어떻게 되나?
> ZSCORE game "newbie"
```
> 💡 ZINCRBY는 없는 멤버면 score 0에서 시작. "좋아요 수 랭킹" 등에 핵심.

---

### Q6. ★★★ 🪤 ZADD 옵션 — NX / XX
```
> DEL board
> ZADD board 100 "alice"
> ZADD board NX 200 "alice"       ← NX=없을 때만. 이미 있으니? (갱신될까?)
> ZSCORE board "alice"            ← 100? 200?
> ZADD board XX 300 "bob"         ← XX=있을 때만. "bob" 없으니? (추가될까?)
> ZSCORE board "bob"
```
> 🪤 NX=신규만(기존 갱신 안 함), XX=기존만(신규 추가 안 함). String SET의 NX/XX와 같은 결.

---

### Q7. ★★★ 🪤 ZADD 옵션 — GT / LT
```
> DEL board
> ZADD board 100 "alice"
> ZADD board GT 50 "alice"        ← GT=새 score가 더 클 때만 갱신. 50<100이니?
> ZSCORE board "alice"            ← 100? 50?
> ZADD board GT 200 "alice"       ← 200>100이니 갱신?
> ZSCORE board "alice"
```
> 💡 GT(greater than)=최고 점수만 유지. 리더보드에서 "기록 경신할 때만 갱신"에 딱. LT는 반대.

---

### Q8. ★★ ZADD CH / INCR 옵션
```
> DEL board
> ZADD board 100 "a" 200 "b"
> ZADD board CH 100 "a" 250 "b"   ← CH=변경된(changed) 멤버 수 반환 (추가+갱신)
> ZADD board INCR 10 "a"          ← INCR=ZINCRBY처럼 동작, 새 score 반환
```

## §2. ZRANK / ZREVRANK — 순위 (대기열 순번의 핵심)

### Q9. ★★ 🎟 ZRANK
```
> DEL q
> ZADD q 100 "user1" 200 "user2" 300 "user3"
> ZRANK q "user1"                 ← 순위? (0부터? score 낮은 게 0?)
> ZRANK q "user3"
> ZRANK q "nope"                  ← 없는 멤버?
```
> 💡 ZRANK = score **오름차순** 순위(0-based). 대기열 "내 앞에 몇 명?"에 직결.

---

### Q10. ★★ 🏆 ZREVRANK
```
> ZREVRANK q "user3"              ← 내림차순 순위. score 높은 게 0
> ZREVRANK q "user1"
```
> 🏆 리더보드는 보통 ZREVRANK (높은 점수가 1등).

---

### Q11. ★★★ 🪤 ZRANK WITHSCORE (7.2+)
```
> ZRANK q "user2" WITHSCORE       ← 순위와 score를 함께
```

## §3. ZRANGE 계열 — 3가지 축으로 조회 (가장 중요)

### Q12. ★★ ZRANGE by 인덱스(rank)
```
> DEL board
> ZADD board 10 "a" 20 "b" 30 "c" 40 "d" 50 "e"
> ZRANGE board 0 2                ← 인덱스 0~2 (score 오름차순). 누구?
> ZRANGE board 0 -1               ← 전체
> ZRANGE board 0 -1 WITHSCORES    ← score도 함께
```

---

### Q13. ★★ 🏆 ZREVRANGE
```
> ZREVRANGE board 0 2 WITHSCORES  ← 내림차순 상위 3 (리더보드 TOP 3)
```

---

### Q14. ★★★ 🎟 ZRANGEBYSCORE — score 구간
```
> ZRANGEBYSCORE board 20 40       ← score 20~40 (양끝 포함)
> ZRANGEBYSCORE board 20 40 WITHSCORES
> ZRANGEBYSCORE board -inf +inf   ← 전체 (무한대 표기)
```
> 💡 `-inf`/`+inf`로 무한대. Rate Limit·시간 윈도우 조회의 핵심.

---

### Q15. ★★★ 🪤 ZRANGEBYSCORE 경계 — 배타(exclusive)
```
> ZRANGEBYSCORE board (20 40      ← "(20" = 20 초과(20 제외). 어떻게 다른가?
> ZRANGEBYSCORE board 20 (40      ← "(40" = 40 미만(40 제외)
```
> 🪤 `(` 접두사 = 경계 제외. 기본은 포함. 시간 윈도우 "이상/초과" 구분에 중요.

---

### Q16. ★★★ 🎟 ZRANGEBYSCORE LIMIT (페이지네이션)
```
> ZRANGEBYSCORE board -inf +inf LIMIT 0 2    ← offset 0, count 2
> ZRANGEBYSCORE board -inf +inf LIMIT 2 2    ← offset 2, count 2
```
> 💡 LIMIT offset count로 페이징. 큰 ZSet을 나눠 가져올 때.

---

### Q17. ★★★★ 🪤 ZRANGE 통합 문법 (Redis 6.2+)
```
> ZRANGE board 20 40 BYSCORE              ← ZRANGEBYSCORE와 동일
> ZRANGE board 0 2 REV                    ← ZREVRANGE와 동일
> ZRANGE board (20 40 BYSCORE LIMIT 0 2   ← 옵션 조합
```
> 💡 6.2부터 ZRANGE 하나로 BYSCORE/BYLEX/REV/LIMIT 통합. 구버전 ZREVRANGE/ZRANGEBYSCORE는 유지되지만 신규는 ZRANGE 권장.

---

### Q18. ★★★★ 🪤 ZRANGEBYLEX — 사전순 (같은 score일 때만)
```
> DEL names
> ZADD names 0 "apple" 0 "banana" 0 "cherry" 0 "date"   ← score 전부 0
> ZRANGEBYLEX names - +                    ← 전체 사전순
> ZRANGEBYLEX names [b [d                   ← "b"~"d" 범위 ([=포함)
> ZRANGEBYLEX names (apple +                ← apple 초과
```
> 🪤 ZRANGEBYLEX는 **모든 멤버 score가 같을 때만** 의미 있음. score 다르면 결과 미정의. 자동완성·사전식 인덱스에 쓰임.

## §8. 집합 연산 🔀 ZUNIONSTORE / ZINTERSTORE (score 합산)

### Q32. ★★★ 🔀 ZUNIONSTORE — 합집합 (score 합산)
```
> DEL a b dest
> ZADD a 10 "x" 20 "y"
> ZADD b 5 "y" 30 "z"
> ZUNIONSTORE dest 2 a b          ← 합집합. "y"의 score는? (20+5=25?)
> ZRANGE dest 0 -1 WITHSCORES
```
> 🪤 numkeys(2) 먼저! 그리고 같은 멤버는 **score가 합산(기본 SUM)**.

---

### Q33. ★★★★ 🔀 WEIGHTS — 가중치
```
> DEL dest
> ZUNIONSTORE dest 2 a b WEIGHTS 1 2   ← a는 ×1, b는 ×2 후 합산
> ZRANGE dest 0 -1 WITHSCORES          ← "y" = 20×1 + 5×2 = 30?
```
> 💡 WEIGHTS로 각 집합 score에 가중치. "최근 활동 2배 가중" 같은 랭킹에.

---

### Q34. ★★★★ 🔀 AGGREGATE — 합산 방식
```
> DEL dest
> ZUNIONSTORE dest 2 a b AGGREGATE MAX   ← 합산 대신 MAX
> ZRANGE dest 0 -1 WITHSCORES            ← "y" = max(20,5)=20?
```
> 💡 AGGREGATE SUM(기본)/MIN/MAX. 여러 랭킹 병합 시 "최고 점수만" 등.

---

### Q35. ★★★ 🔀 ZINTERSTORE / ZINTERCARD / ZDIFF
```
> ZINTERSTORE dest 2 a b          ← 교집합 (둘 다 있는 멤버, score 합산)
> ZRANGE dest 0 -1 WITHSCORES     ← "y"만?
> ZINTERCARD 2 a b                ← 교집합 개수만 (7.0+)
> ZDIFF 2 a b                     ← 차집합 (a에만, 7.0+ STORE 없는 버전)
```

### Q42. ★★★★★ 🎟 Rate Limit (Sliding Window Log)
```
[사용자가 10초에 3회만 허용. score=요청 시각(ms)]
> DEL rl:user:1
> ZADD rl:user:1 1000 "req-1000"          ← 1초 시점 요청

> (count < 3 이면 허용하고 ZADD, 아니면 거부)
```
