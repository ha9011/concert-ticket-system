# Sorted Set 실습 — 개념 정리 & 실무 활용 요약

> 72문항 실습 후 가볍게 읽으며 머릿속 정리용. 문법보다 **"왜 이 명령어가 있고, 실무에서 어떻게 쓰이는가"**에 무게.
> ZSet 한 문장: **"멤버마다 score가 붙어 score 순으로 자동 정렬되는 Set. 랭킹·범위·순위가 O(log N)."**

---

## §0. ZSet이란 무엇인가 — 한 장 정리

```
   ZSet = { (member, score) ... }   ← 멤버 유일(중복X), score로 자동 정렬

   ZADD board 2100 "faker"
   ZREVRANGE board 0 2 WITHSCORES   → score 높은 순 TOP 3
   ZRANK board "faker"              → score 오름차순 순위(0-based)
   ZRANGEBYSCORE board 1900 2200    → score 구간 조회
```

- **멤버 = 유일** (Set처럼 중복 없음). 각 멤버에 **score(64비트 double)** 1개.
- **score 순 자동 정렬** → 삽입/삭제/순위/범위 조회가 **O(log N)** (내부 skiplist).
- **동점(같은 score) → 멤버 사전순(lexicographical)** 으로 정렬. (이게 ZRANGEBYLEX의 전제)
- **빈 컬렉션 = 키 삭제**: 멤버 0개가 되면 키 자동 소멸.

> 💡 한 줄 비교: **List**=순서(삽입순), **Set**=중복 없는 모음, **ZSet**=score로 정렬된 모음. "정렬·순위·범위가 필요하면 ZSet."

---

## §1. 추가·점수 — ZADD / ZSCORE / ZINCRBY

| 명령어 | 동작 | 비고 |
|---|---|---|
| `ZADD k score m [score m...]` | 추가/갱신 | 같은 멤버는 **score 갱신** |
| `ZSCORE k m` / `ZMSCORE k m...` | score 조회 | 없으면 nil |
| `ZINCRBY k delta m` | score 증가 | 없는 멤버는 0에서 시작 |

### ZADD 옵션 (헷갈림 1순위 🪤)

| 옵션 | 의미 |
|---|---|
| `NX` | 멤버 **없을 때만** 추가 (기존 score 안 건드림) |
| `XX` | 멤버 **있을 때만** 갱신 (신규 추가 안 함) |
| `GT` | 새 score가 **기존보다 클 때만** 갱신 (최고 기록 유지) |
| `LT` | 새 score가 **기존보다 작을 때만** 갱신 |
| `CH` | 반환값을 "변경된(changed) 멤버 수"로 (추가+갱신) |
| `INCR` | ZINCRBY처럼 동작, 새 score 반환 |

### 핵심 포인트

- **같은 멤버 ZADD = score 덮어쓰기.** 반환값 기본은 "새로 추가된 멤버 수"(갱신은 0). `CH` 주면 변경 수.
- **GT가 리더보드의 친구** — "기록 경신할 때만 갱신"은 `ZADD board GT score user`. 낮은 점수로 덮어쓰는 사고 방지.
- **ZINCRBY는 누적 카운터 랭킹** — 좋아요/조회수 랭킹에서 멤버 점수 누적.

## §2. 순위 — ZRANK / ZREVRANK (대기열·등수의 핵심)

| 명령어 | 동작 |
|---|---|
| `ZRANK k m` | score **오름차순** 순위 (0-based) |
| `ZREVRANK k m` | score **내림차순** 순위 (0-based) |
| `ZRANK k m WITHSCORE` | 순위 + score 함께 (7.2+) |

### 핵심 포인트

- **ZRANK = 오름차순(작은 score가 0위)** → 대기열 "내 앞에 몇 명?"(먼저 온 사람=낮은 timestamp=앞 순위).
- **ZREVRANK = 내림차순(높은 score가 0위)** → 리더보드 "내 등수"(높은 점수=1등). 등수는 `ZREVRANK + 1`.
- 둘 다 **O(log N)** — 1000만 명 중 내 순위를 즉시. RDB `ORDER BY ... COUNT`로는 느린 걸 ZSet은 상수에 가깝게.

---

## §3. 범위 조회 — ZRANGE 3가지 축 (가장 중요)

ZSet 조회는 **세 가지 기준**으로 가능하다:

| 축 | 명령 | 의미 |
|---|---|---|
| **인덱스(rank)** | `ZRANGE k start stop` | 정렬 순서상 N번째~M번째 |
| **score** | `ZRANGE k min max BYSCORE` (=`ZRANGEBYSCORE`) | score 구간 |
| **사전순(lex)** | `ZRANGE k min max BYLEX` (=`ZRANGEBYLEX`) | 멤버 이름 사전순(**score 동일 전제**) |

### 핵심 포인트

- **6.2+ 통합 문법**: `ZRANGE`에 `BYSCORE`/`BYLEX`/`REV`/`LIMIT` 옵션을 붙여 다 처리. 구버전 `ZREVRANGE`·`ZRANGEBYSCORE`·`ZRANGEBYLEX`도 동작하지만 신규는 ZRANGE 권장.
- **`WITHSCORES`** — score도 함께 반환 (리더보드 표시용).
- **🪤 경계 배타 `(`** — `(20`=20 초과(제외), `[20`(lex)=20 포함. score 윈도우 "이상/초과" 구분에 중요.
- **`-inf` / `+inf`** — score 무한대. 전체 조회·시간 윈도우에.
- **`LIMIT offset count`** — 페이지네이션 (BYSCORE/BYLEX와 함께).
- **🪤 ZREVRANGEBYSCORE는 max min 순서** — `ZREVRANGEBYSCORE k 40 20`(큰 값 먼저). 방향 헷갈림 주의.
- **🪤 BYLEX는 모든 score가 같을 때만** 의미. score 다르면 결과 미정의. 자동완성·사전 인덱스용.

## §4. 세기 — ZCARD / ZCOUNT / ZLEXCOUNT

| 명령어 | 동작 | 비고 |
|---|---|---|
| `ZCARD k` | 전체 멤버 수 | O(1) |
| `ZCOUNT k min max` | score 구간 멤버 수 | O(log N) |
| `ZLEXCOUNT k min max` | 사전순 구간 수 | score 동일 전제 |

- **Rate Limit "윈도우 내 요청 수"** = `ZCARD`(전체) 또는 `ZCOUNT`(구간). 오래된 걸 먼저 ZREMRANGEBYSCORE로 지우면 ZCARD로 충분.

---

## §5. 추출 — ZPOPMIN / ZPOPMAX / BZPOPMIN

| 명령어 | 동작 |
|---|---|
| `ZPOPMIN k [count]` | **최소 score** 멤버 꺼내며 제거 |
| `ZPOPMAX k [count]` | **최대 score** 멤버 꺼내며 제거 |
| `BZPOPMIN/MAX k timeout` | 블로킹 버전 |

### 핵심 포인트

- **ZPOPMIN = "가장 우선(낮은 score)" 소비** → 우선순위 큐·지연 큐 소비의 핵심. (score=실행시각이면 "가장 먼저 실행할 작업"이 ZPOPMIN)
- **BZPOPMIN = List BRPOP의 ZSet판** — 비면 대기, 들어오면 깨어남. 단 꺼내는 기준이 FIFO가 아니라 **score 최소**. → "우선순위 + 블로킹 소비".

---

## §6. 제거 — ZREM / ZREMRANGEBY*

| 명령어 | 동작 | 용도 |
|---|---|---|
| `ZREM k m...` | 멤버 제거 | 개별 |
| `ZREMRANGEBYRANK k start stop` | 순위 구간 제거 | **상위 N만 유지**(하위 잘라냄) |
| `ZREMRANGEBYSCORE k min max` | score 구간 제거 | **윈도우 밖/만료** 정리 |
| `ZREMRANGEBYLEX k min max` | 사전순 구간 제거 | score 동일 전제 |

- **리더보드 capped** = `ZREMRANGEBYRANK board 0 -(N+1)` 류로 하위 정리 (List LTRIM에 해당).
- **Rate Limit/지연 큐 정리** = `ZREMRANGEBYSCORE k -inf {기준시각}`로 오래된 것 제거.

---

## §7. 집합 연산 🔀 ZUNIONSTORE / ZINTERSTORE (score 합산이 포인트)

| 명령어 | 동작 |
|---|---|
| `ZUNIONSTORE dest numkeys k... [WEIGHTS..] [AGGREGATE..]` | 합집합, score 합산 |
| `ZINTERSTORE dest numkeys k...` | 교집합, score 합산 |
| `ZUNION/ZINTER/ZDIFF numkeys k...` | STORE 없는 버전 (6.2/7.0+) |
| `ZINTERCARD numkeys k... [LIMIT n]` | 교집합 개수만 (7.0+) |

### 핵심 포인트

- **🪤 numkeys 먼저** — `ZUNIONSTORE dest 2 a b` (키 2개라고 명시). Set과 달리 ZSet 집합연산은 numkeys 필수.
- **같은 멤버 score는 합산(기본 SUM)** — 두 랭킹의 같은 유저 점수가 더해짐.
- **WEIGHTS** — 각 집합 score에 가중치. `WEIGHTS 1 2` = 첫 집합 ×1, 둘째 ×2. "최근 7일 2배 가중 랭킹" 등.
- **AGGREGATE SUM(기본)/MIN/MAX** — 합산 방식. 여러 랭킹 병합 시 "최고 점수만"=MAX.

## §8. 인코딩 / 운영

- **인코딩 2단계**:
  - **listpack** — 작을 때(연속 메모리, 캐시 친화적).
  - **skiplist(+해시)** — 커지면. score 정렬은 skiplist, 멤버→score 조회는 해시로 O(1).
  - 경계: `zset-max-listpack-entries`(기본 128), `zset-max-listpack-value`(기본 64바이트).
- **big key 주의** — 큰 ZSet `DEL`은 블로킹 → `UNLINK`. 큰 `ZRANGE 0 -1`도 위험(전부 직렬화).
- **WRONGTYPE** — 다른 타입 키에 ZSet 명령 = 에러.
- **멤버 개별 TTL 불가** — TTL은 키 단위만. **멤버 만료는 score=만료시각 + 주기적 ZREMRANGEBYSCORE**로 흉내.

---

## 🎯 ZSet 핵심 패턴 8개 (실무 빈출)

1. **리더보드** — `ZADD GT` + `ZREVRANGE WITHSCORES` + `ZREVRANK`(등수)
2. **선착순 대기열** — score=진입시각, `ZRANK`(순번) + `ZRANGE/ZREMRANGEBYRANK`(통과)
3. **우선순위 큐** — score=우선순위, `ZPOPMIN`(또는 BZPOPMIN)
4. **Rate Limit(Sliding Window Log)** — score=요청시각, `ZREMRANGEBYSCORE`+`ZCARD`
5. **지연 큐(delayed job)** — score=실행시각, `ZRANGEBYSCORE -inf now`로 "지금 실행할 것"
6. **가중 추첨** — score=누적 가중치 (Set SPOP의 균등 추첨 한계 해결)
7. **최근/capped 목록** — score=timestamp, `ZREMRANGEBYRANK`로 N개 유지
8. **멤버 만료 흉내** — score=만료시각, 주기적 `ZREMRANGEBYSCORE`

---

## ⚠️ 운영에서 깨지기 쉬운 약속 6가지

1. **큰 `ZRANGE 0 -1`을 쓰지 않는다** — LIMIT 페이지네이션으로.
2. **빈 ZSet은 키가 사라진다** — `EXISTS` 존재 체크 혼동 금지.
3. **멤버 개별 TTL은 없다** — score=만료시각 패턴으로.
4. **ZUNIONSTORE/ZINTERSTORE는 numkeys 필수 + score 합산** — 의도와 다른 합산 주의(AGGREGATE).
5. **Rate Limit의 제거→카운트→추가는 Lua로 원자화** — 따로 하면 동시성 구멍.
6. **score는 double** — 큰 정수(예: 나노초 ID)는 정밀도 손실 가능. 53비트 초과 정수 주의.

## 📌 면접에서 잘 나오는 비교 질문

| 질문 | 답 |
|---|---|
| Set vs ZSet | Set=정렬 없음, ZSet=score 정렬 + 순위/범위 O(log N). |
| ZRANK vs ZREVRANK | 오름차순 vs 내림차순 순위. 등수=ZREVRANK+1. |
| ZSet 내부 구조 | skiplist(정렬) + 해시(멤버→score O(1)). |
| 리더보드를 RDB로? | `ORDER BY+LIMIT`은 데이터 커지면 느림. ZSet은 O(log N) 일정. |
| 동점 처리 | 같은 score면 멤버 사전순. tie-break 필요하면 score에 정보 인코딩. |
| ZSet으로 대기열 | score=진입시각, ZRANK=순번, ZREMRANGEBYRANK=통과. |
| ZSet으로 Rate Limit | Sliding Window Log: score=요청시각, ZREMRANGEBYSCORE+ZCARD. |
| WEIGHTS/AGGREGATE | 집합 합산 시 가중치/합산방식(SUM/MIN/MAX). |

## ZSet vs List vs Set (언제 무엇)

| 필요 | 자료구조 |
|---|---|
| 삽입 순서 그대로 (큐/스택/로그) | **List** |
| 중복 없는 멤버십·집합 연산 | **Set** |
| **점수로 정렬 / 순위 / score 범위** | **ZSet** |
| 우선순위 큐 (FIFO 아님) | **ZSet**(ZPOPMIN) — List BRPOP은 FIFO만 |

> 핵심: **"순서가 '점수'로 정해지고, 순위·범위·top-N이 필요하면 ZSet."** 단순 FIFO면 List로 충분(ZSet은 오버킬).
